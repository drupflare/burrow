    Interface ProbeOptions

    Deploying a throwaway Worker, measuring it on the edge, and tearing it down.

    An in-worker clock reads 0 on the deployed edge, and local-to-edge factors run 2.2x to 6.1x, so a performance claim about a runtime has to come from a deploy.

    It reports end-to-end latency from the client. CPU time is not readable from here; that needs wrangler tail against ProbeResult.scriptName while the script is up.

    Teardown runs in a finally, so a probe that throws still deletes what it deployed.
